# 全面数字化商务与工程结算审计系统端到端落地实施方案

## 编写说明与制度基准

本方案依据中国建筑股份有限公司及中国建筑第四工程局有限公司现行《建设工程商务管理手册》《工程成本管理办法》《工程结算管理办法》《项目全周期现金流预算管理办法》《催收清欠工作管理办法》（中建四商〔2023〕10号）以及《违规经营投资责任追究办法》编制。

**核心架构原则**：

1. **算法与定性分离铁律**​：算量、比价、比例倒挂、超耗金额、时序偏差等量化指标由 ​**Python 确定性规则引擎硬算**（确保 100% 可举证、可复现）；大模型（LLM）仅用于非结构化合同条款语义定性、责任归属判定与审计底稿文本组织。
2. **多源证据交叉验证铁律**：单一数据源命中仅作为“疑点线索”；必须通过“合同、台账、结算表、现场日志、财务凭证、业主清单”三向及以上交叉印证，证据计数 $\ge 2$ 方可坐实为审计发现问题。
3.  **“双轨为经、穿透为纬”立体风控**：以“对上业主工程结算（收入轨）”与“对下分包分供结算（成本轨）”为业务主线，全面穿透“工程现场实体、财务资金账目、法务风控底线、营销源头测算”，彻底打破商务“纸面手续合规、现场实质失血”的合规陷阱。

### 2. 统一数据模型定义（Canonical Schema）

系统以 **​`contract_no`​**​ **（合同编号）**  与 **​`project_no`​**​ **（项目 WBS 编码）**  为锚点构建统一中间表，禁止模型跨原始文件自由读取：

```
project 项目实体 (1) ── [project_no]
   │
   ├── contract 分包合同实体 (n) ── [contract_no]
   │      ├── contract_line_item   合同清单明细 (n)
   │      ├── settlement           结算审定主表 (n)
   │      │     └── settlement_line_item  结算清单明细 (n) [category: 合同清单 / 签证 / 扣款 / 其他]

   │      ├── variation            签证与索赔实体 (n)
   │      ├── approval_decision    审批决策实体 (n) [三重一大 / 董事会纪要]
   │      └── supplementary_agree  补充协议实体 (n)
   │
   ├── owner_settlement_item 业主结算清单项 (n) [以 item_code / item_name 关联]
   ├── construction_diary    施工日志实体 (n) [以 project_no + 日期关联]
   └── sap_account_balance   财务与资金账套实体 (1) [以 project_no 关联]
```

## 维度一：对上业主工程结算与收入确权穿透（收入轨）

---

### 模型 1.1：外报量确权率偏离与超前确权检测模型

#### 1. 模型定位与业务痛点

- **业务定位**：穿透“现场实际完成产值”与“对上业主确权产值”的匹配度，双向拦截“确权滞后失血”与“跨期虚增业绩”。
- **痛点场景**：现场完成 1 亿仅确权 7000 万导致大额垫资；或为冲考核在未完工部位提前确认产值。

#### 2. 多源数据输入

- `completed_output`​（现场实测完成产值）、`confirmed_output`​（业主确权产值）、`construction_diary`（施工日志部位）。

#### 3. 逻辑判别路径（决策树）

```
                       [计算确权率 = 业主确权产值 / 实际完成产值]
                                      │
         ┌────────────────────────────┼────────────────────────────┐
         ▼                            ▼                            ▼
   【确权率 < 95%】           【95% ≤ 确权率 ≤ 110%】        【确权率 > 110%】
         │                            │                            │
         ▼                            ▼                            ▼
 [判定: 对上确权严重滞后]         [判定: 确权处于正常合理区间]   [比对施工日志与现场实体]
         │                            │                            │
         ▼                            ▼                ┌───────────┴───────────┐
 [测算应确未确资金缺口]          [PASS: 流程放行]              ▼                       ▼
 [触发红线预警与催签指令]                               【现场部位已完工】     【现场部位未完工】
                                                               │                       │
                                                               ▼                       ▼
                                                      [认定为合规进度款调整]   [判定: 提前确认产值虚增业绩]
                                                                                       │
                                                                                       ▼
                                                                               [强制调减当期入账收入]

```

#### 4. 核心规则与门限

- **规则 1.1-A**：确权率 $<95\%$ 且产生应确未确差额 $\text{Gap} = \text{完成产值} \times 0.95 - \text{确权产值}$，触发红色预警；
- **规则 1.1-B**：确权率 $>110\%$ 且日志显示部位未完工，判定为“虚增产值”。

#### 5. 审计定性公文

>  **【定性】** ：对上确权严重滞后突破合规底线；  
>  **【量化】** ：项目累计完成产值 4.12 亿元，业主确权仅 3.86 亿元（确权率 93.81%），形成 2.48 亿元应确未确资金敞口；

#### 第一部分：商务与结算合规四链

##### 链 1　先干后谈与未定价变更责任错配链

**演进路径**：口头/会议越权指令 → 模型 2.4（未签合同先进场） → 模型 1.3（变更超 14 天未办经济确权） → 模型 2.2（结算申报清单外项被全额核减）。

**业务机理与深层痛点**：将决定拆分为现场“必须马上干”与商务“以后审价”两次决定。工程端取得即时进度，商务端保留审价空间，现场材料已采购、隐蔽已覆盖，导致证据灭失、成本混淆入原合同，项目部被迫承担现金垫资与结算让价双重损失。

> **智能体三段式公文定论**
> - 【定性判断】：项目违规执行“先干后谈”，存在严重的时序错配与管理责任转嫁；
> - 【量化支撑】：未定价变更先行施工 2.4 个月，导致 209 万元新增成本混入原合同且缺乏有效图纸和签认证据，结算时被迫折让核减 180 万元；
> - 【管理定论】：暴露出上级越权下达口头指令而回避经济后果的坏管理，系统依据“一页最低确认机制”将指令发起人锁定为风险第一责任人。

##### 链 2　结算滞后与虚盈实亏时间亏损链

**演进路径**：模型 1.1（外报量确权偏离） → 模型 1.2（久竣未结超期 515 天） → 模型 3.1（存货未报耗挂账 868 万） → 模型 3.2（产生贴息利息 8424 万）。

**业务机理与深层痛点**：项目为冲产值提前确认虚高收入，竣工后因资料不齐、签证未闭合拖延结算，形成大额“应收未结”挂账。账面利润被长周期的年化资金利息（3.5%–5%）吞噬，形成典型的“时间型亏损”。

> **智能体三段式公文定论**

```
    overuse_qty = material.actual_quantity - allowed_quantity
    if overuse_qty > 0:
        required_deduct_amount = overuse_qty * material.purchase_unit_price * contract.overuse_deduct_multiplier # 1.5倍扣减
        actual_deducted = sum(d.amount for d in settlement_deduct_items if material.name in d.name)
        if actual_deducted < required_deduct_amount:
            return {"hit": True, "risk": "高风险", "overuse_qty": overuse_qty, "short_deduct_amount": required_deduct_amount - actual_deducted}
    return {"hit": False}

# 模型 2.4：未签合同先进场时序倒置模型
def model_2_4_entry_before_contract(contract, diary_first_date):
    if diary_first_date and contract.sign_date:
        days_diff = (contract.sign_date - diary_first_date).days
        if days_diff > 0: # 进场早于签订
            return {"hit": True, "risk": "较大违规", "days_diff": days_diff, "rule": f"未签合同先进场施工 {days_diff} 天"}
    return {"hit": False}

# 模型 2.5：分包代工与负结算未结清收模型
def model_2_5_third_party_labor_deduct(settlement, third_party_labors):
    un_deducted_labor = sum(l.amount for l in third_party_labors if not l.is_deducted_in_settlement)
    is_negative_settlement = settlement.audit_amount < 0
    if un_deducted_labor > 0 or is_negative_settlement:
        return {"hit": True, "risk": "高风险", "un_deducted_amount": un_deducted_labor, "negative_amount": abs(settlement.audit_amount) if is_negative_settlement else 0}
    return {"hit": False}


# ==============================================================================
# 维度三：业财法工全域穿透与真实效益还原算法闭环
# ==============================================================================

# 模型 3.1：存货未报耗虚增利润模型
def model_3_1_inventory_unexpensed_check(project, sap_inventory_balance, current_date):
    if project.status == "竣工" and sap_inventory_balance > 0:
        days_after_acceptance = (current_date - project.acceptance_date).days
        if days_after_acceptance > 30:
            return {"hit": True, "risk": "一般违规", "fictitious_profit": sap_inventory_balance, "rule": "竣工超30天原材料未报耗挂账虚增利润"}
    return {"hit": False}

# 模型 3.2：隐性贴息利息侵蚀与真实效益还原模型
def model_3_2_real_profit_reduction(project, sap_interest_fees):
    # 真实利润 = 账面审定利润 - (内部借款利息 + 供应链贴息 + 钢材逾期利息)
    total_interest = sum(sap_interest_fees.values())
    real_profit = project.book_profit - total_interest
    is_real_loss = (project.book_profit > 0) and (real_profit < 0)
    return {"hit": is_real_loss or total_interest > 1000000, "real_profit": real_profit, "eroded_interest": total_interest, "is_real_loss": is_real_loss}

# 模型 3.3：招采付款倒挂与强制止损模型
def model_3_3_procurement_inversion_and_stop_loss(contract, subcontract, project):
    # 倒挂: 对上收款比例 < 对下付款比例
    is_inversion = contract.progress_pay_ratio < subcontract.progress_pay_ratio
    # 止损: 业主拖欠超 30% 且超 12 个月未停工
    is_stop_loss_triggered = (project.owner_default_ratio > 0.30) and (project.owner_default_months > 12) and (project.status != "停工")
    return {"hit": is_inversion or is_stop_loss_triggered, "is_inversion": is_inversion, "is_stop_loss_triggered": is_stop_loss_triggered}
```

#### 算法公式定义：

- **结算风险维度** **$R \in [1.0, 3.0]$**：

  $$
  R = \frac{\text{超结审批风险} \times 1.0 + \text{清单外虚假风险} \times 1.0 + \text{材料超耗漏扣} \times 0.8 + \text{确权久竣未结} \times 0.8 + \text{招采倒挂高压} \times 0.4}{4.0}
  $$
- **真实效益维度** **$E \in [1.0, 3.0]$**：

  $$
  E = \frac{\text{还原后真实利润率} \times 1.05 + \text{外报量确权率} \times 0.75 + \text{资金回款比例} \times 0.75 + \text{结算审定规模} \times 0.45}{3.0}
  $$
