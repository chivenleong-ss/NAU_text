# 统一数据模型定义（Canonical Schema）

> **目的**：一份"中间表"——所有审计模型（规则引擎、专家智能体、RAG 问答）统一从这里取数，不再各读各的原始文件。
>
> **主键**：合同编号（contract_no）。整个模型以"合同"为锚点，向上下关联项目、清单、结算、材料、签证、审批、施工日志。
>
> **来源标注**（每个字段标注数据从哪来、怎么拿）：
> - 🟢 结构化表格 —— Excel/CSV，直接读单元格
> - 🟡 Word 正文 —— 合同/制度正文，关键词抽取或 LLM 语义抽取
> - 🔴 纸质/扫描件 —— 需 OCR + 版面分析后抽取

---

## 一、实体关系总览

```
project 项目 (1)
   └── contract 分包合同 (n)                ← 主键 contract_no
          ├── contract_line_item   合同清单项 (n)
          ├── settlement           结算 (n)
          │     └── settlement_line_item  结算清单项 (n)   ← 类别字段区分：合同清单/签证/扣款
          ├── material             物资进场验收台账 (n)
          ├── variation            签证 (n)
          ├── approval_decision    审批决策（三重一大/补充协议）(n)
          ├── supplementary_agreement  补充协议 (n)
          └── (关联) owner_settlement_item  业主结算清单项 (n)  ← 按"清单编码/项目名称"匹配

construction_diary 施工日志 (独立，按工程名称+日期关联)
```

**规则引擎落点**（6 条规则 + 262 条制度规则，全部映射到上表字段）：

| 规则 | 依赖字段 |
| --- | --- |
| 规则一：结算额 vs 合同额 5% 阈值 | contract.合同价 vs settlement.审定金额 + approval_decision / supplementary_agreement |
| 规则二：禁止签证却出现签证 | contract.禁止签证 vs settlement_line_item.类别=签证 |
| 规则三：材料超用未扣 | contract.损耗率/超耗扣款倍数 vs material.预算量/领用量 vs settlement_line_item.扣款 |
| 规则四：未签合同先进场 | contract.签订日期 vs construction_diary.日期 |
| 规则五：同区同类型价格低 15% | contract_line_item.单价（横向跨合同比较）|
| 规则六：清单外项 | settlement_line_item vs contract_line_item vs owner_settlement_item |

## 三、关键设计说明

1. **不建"一张超宽表"**：合同→结算→清单是 1:N 关系，一张宽表会重复爆炸。用"实体 + 外键"建模，Python 规则引擎用 `DataFrame`/字典 join 即可。
2. **category 字段是规则引擎的枢纽**：结算清单项标注了"合同清单/签证/扣款"三类，规则二（禁止签证）、规则三（超耗扣款）、规则六（清单外项）都靠它判断。
3. **规则一需要跨文件**：合同价（contract）vs 审定金额（settlement），再回查有没有"三重一大"决策（approval_decision）和补充协议（supplementary_agreement）——这两类文件通常是纸质，见《字段来源清单》。
4. **主键统一用 contract_no**：结算台账、合同、结算附表、清单计价表都以合同编号对齐，是天然的关联键。
